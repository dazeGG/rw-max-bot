# Дев-стенд

Сервер `193.233.91.146` (Санкт-Петербург), дев-бот и админка. Схема как у заказчика: вебхук и админка на разных адресах.

| Адрес | Что на нем |
|-------|------------|
| `rw-bot.dazinho.ru` | только `/webhook`, остальное 404 |
| `admin-rw-bot.dazinho.ru` | админка и `/api` |

На стенде только начальный контент и тестовые пользователи: дампы прода сюда не загружаются.
Админку защищает только вход, внешнего контура заказчика здесь нет.

## Сервер общий с войсрумом

На сервере работает голосовой сервис войсрум, его не трогать. Стенд живет в `/home/daze/rw-max-bot`, пользователь `daze` без sudo.

- Порты 80 и 443 у Caddy войсрума. Он подключает файлы из `~/VoiceRoom/config/caddy/sites.d` (с релиза войсрума 2.12.18),
  наш файл `deploy/dev/voiceroom-sites.caddy` кладет туда `deploy.sh`. Перед перечитыванием конфиг проверяется:
  ошибка в файле сайтов не дала бы Caddy войсрума запуститься.
- Контейнер `web` стенда подключен к сети `voiceroom_default`. В ней есть свои `api` и `postgres`, поэтому наши сервисы
  в Caddy стенда названы уникально: `rw-max-bot-api`, `rw-max-bot-bot`.
- Бот работает без реранкера (`RERANK_DEPTH=0`) и с лимитом в одно ядро и 1 ГБ: память нужна войсруму.
  Ответы на свободные вопросы поэтому хуже, чем на проде; качество поиска проверяется локально.

```bash

```

## Обслуживание

```bash
ssh daze@193.233.91.146
cd ~/rw-max-bot/src/deploy
alias dc='docker compose -f docker-compose.yml -f dev/docker-compose.yml --env-file ~/rw-max-bot/.env'

dc ps
dc logs -f bot
dc exec api node --import tsx src/cli/create-admin.ts admin   # создать суперадмина или сбросить ему пароль
```
